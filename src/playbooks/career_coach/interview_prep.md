# Interview Prep — career_coach playbook

Lazy workstream. Trigger: the user names a specific upcoming interview and
asks for prep material.

Every interview maps to an existing row in the applications tracker; this
workstream never creates a new row; treat the JD, company research, and fit
notes already on that row as the starting context rather than re-deriving
them from scratch. If the user names an interview with no matching row, ask
them to confirm the company/role rather than guessing which application it
belongs to.

Produce a prep sheet covering: the confirmed role and interview stage (if
known), a refreshed narrative-hook summary pulled from the original triage
and letter (don't regenerate the fit analysis from zero), likely questions
for this stage and role level, and a short set of the user's own proof points
(from their anecdotes and employment-history context files) matched to those
likely questions. If the user separately asks for a take-home or assignment
deliverable tied to the interview, treat that as its own output, distinct
from the prep sheet.

Voice and factual-accuracy rules mirror `cover_letter.md`: never invent an
experience, metric, or outcome not present in the user's own context files.
Prep sheets are working documents for the user, not polished prose for an
external reader, so the lint gate and voice-profile read that gate cover
letters don't apply here unless the user is drafting something they'll say
or send verbatim.

Save the sheet to `applications/interview_prep/prep-sheets/` in the user's
own data root; a separate assignment deliverable (if requested) goes in
`applications/interview_prep/assignments/`. Deliver in chat too, but the
saved file is what makes this a long-term record instead of scrollback.
